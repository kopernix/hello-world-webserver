# AGENTS.md

Context for agents working on this project. `README.md` explains usage to the end
user; this covers the **why** behind each decision, what was verified empirically
and how to check that nothing broke. The files are already commented, so do not
repeat here what they say.

## What this is

Minimal web server to check that a host is reachable. Returns a fixed body and a
fixed HTTP status code, over HTTP and HTTPS at the same time, configured through
`.env`.

The original requirement, which overrides everything else: as simple as possible,
copyable to any server, lightweight, and useful for testing connectivity. **This
is not a web application.** No build, no Dockerfile, no application code, no
dependencies.

## Files

| File | What you change it for |
|---|---|
| `compose.yaml` | Image, ports, environment variables, healthcheck, log limits |
| `.env` | The real configuration. The user edits it on every deployment |
| `env.example` | Documented template, copied to `.env` |
| `templates/default.conf.template` | nginx config, generated by `envsubst` |
| `tls/cert.pem`, `tls/key.pem` | The self-signed generic pair that gets committed |
| `scripts/gen-cert.sh` | Regenerates that pair. The only script that changes state |
| `scripts/test.sh` | Smoke tests: brings the stack up on random ports and checks it answers 200 |
| `README.md` | End-user documentation |
| `VERSION` | Single source of truth for the version. Do not repeat it elsewhere |
| `CHANGELOG.md` | Keep a Changelog format, SemVer versions |
| `LICENSE` | MIT |

`.env` is **not** committed: it is machine specific and `.gitignore` excludes it.
`env.example` is what ships.

The version lives in `VERSION` and nowhere else: `CHANGELOG.md` and the git tag
derive from it. Do not hardcode the number in `README.md` or in the compose file,
those go stale. Bump the patch level for fixes, minor for behaviour, major for
breaking the `.env` contract.

Under 50 KB of files and a 21 MB image (`nginx:alpine-slim`).

## Decisions

These are already commented in the files themselves and are not repeated: the
`envsubst` filter, `nc -z` instead of `wget`, mounting `./tls` as a directory,
`default_type` and log rotation. Note the filter is **preventive, not currently
load-bearing**: the template uses no nginx variable, so removing the filter
changes nothing today. It exists so that adding a `$host` later does not silently
break the config, and no test can catch its removal.

What cannot be inferred by reading the code:

- **`return <code> "<text>"` instead of an application.** nginx answers and closes
  the connection, with no backend. That is why changing `STATUS` adds no weight:
  the image is always the same.
- **Generic certificate committed, generated by hand and not on startup.**
  Generating it on startup would require `apk add openssl` on every start,
  network access at startup, or a Dockerfile; and a manual pre-step breaks the
  promise of "copy and run".
- **`-nodes` on the key** (no passphrase): with a passphrase nginx could not start
  unattended under `restart: unless-stopped`.
- **The slim image ships neither `curl` nor `openssl`**, only `nc`, `wget`,
  `envsubst` and the SSL module. That is why the healthcheck uses `nc` and why
  `gen-cert.sh` runs on the host rather than in the container.

## Privacy

The committed certificate is generic on purpose (`CN=helloworld`, SAN
`DNS:localhost, IP:127.0.0.1`): it is identical on every server and leaks nothing
about the machine it was created on. **Do not reintroduce hostname or IPs**;
`gen-cert.sh --host` adds them and its output must not be committed.

Do not write absolute paths containing a user name, hostnames, private IPs or
credentials of any kind. The project has none and should not acquire any: the
only possible secret is `tls/key.pem`, which is the test key, public by design.

## Gotchas

- **`docker compose restart` does NOT re-read the `.env`**: it restarts with the
  configuration already frozen. Use `up -d` for changes. This is the mistake that
  comes up most.
- **`STATUS` takes 100 to 999.** `1000`, `0` or non-numeric text leave nginx in a
  restart loop with `invalid return code` and `docker compose ps` shows
  `Restarting`. Measured with 6 second waits: sampling sooner catches transient
  states of the loop and makes it look like the container is responding.
- **`BODY` accepts no double quotes, no newlines and no `$`.** nginx expands the
  `$` itself: `BODY='$host'` serves the request's host name, and `BODY='100$'`
  gives `invalid variable name` and breaks startup.
- **`BODY=` empty does not give an empty body**, it falls back to `Hello World`,
  because of the `${BODY:-...}` default in the compose file. Allowing an empty
  body would need `${BODY-...}` (single dash). Still undecided.
- **A mismatched TLS pair also takes down HTTP**: nginx does not start, so port 80
  stops answering as well (`key values mismatch`).
- **Binding 80/443 requires root** on the host.
- **There is no `listen [::]`** and none is needed: Docker publishes IPv6 on its
  own.
- **Do not regenerate `tls/` out of habit**: its key is the one already deployed,
  and `--force` forces you to redistribute the certificate.
- **`container_name: helloworld` is a fixed global name.** The stack cannot run
  twice on one Docker host, and `docker compose up` fails with a name conflict if
  an instance is already up. `scripts/test.sh` works around it by renaming both
  the project and the container in its temporary copy, so the tests are safe to
  run against a live deployment. Dropping `container_name` would fix the
  limitation properly, at the cost of the container becoming
  `helloworld-web-1`.

## Verification

After any change. On the development machine port 8080 is taken, which is why the
recipe uses free ports passed through the environment; those take precedence over
the `.env`:

```sh
docker compose config -q                              # syntax

HTTP_PORT=18080 HTTPS_PORT=18443 docker compose up -d
sleep 6 && docker compose ps --format '{{.Status}}'   # healthy

curl -sS -w '  <- %{http_code} %{content_type}\n' http://127.0.0.1:18080/
curl -sS --cacert tls/cert.pem -w '  <- %{http_code}\n' https://localhost:18443/
curl -sSk  -o /dev/null -w '  <- %{http_code}\n' https://127.0.0.1:18443/

sed -i 's/^STATUS=.*/STATUS=499/' .env && docker compose up -d
curl -sS -D- http://127.0.0.1:18080/ | head -1        # HTTP/1.1 499
sleep 5 && docker inspect --format '{{.State.Health.Status}}' helloworld

docker compose down -v
```

To test in a clean slate, copy the project to a temporary directory and work
there (`cp -r <project> /tmp/test && cd /tmp/test`): in the real directory you
would modify the `.env` and the committed certificate. When done, run
`docker compose down -v` and `docker ps -q --filter name=helloworld` must be 0.

## If you need to add something

- **An environment variable**: in `environment` in the compose file, **added to
  `NGINX_ENVSUBST_FILTER`** (otherwise `envsubst` will not substitute it),
  documented in `env.example` and in the `README.md` table.
- **A new `server` or `location`**: in the template, with its own `default_type`.
  When widening the filter, check that nginx variables (`$host`) do not break.
- **Another port**: `.env` and `compose.yaml` together. The internal port is 80 or
  443; only the host port is configurable.
- **A user-visible change**: bump `VERSION`, add a `CHANGELOG.md` entry under
  `Unreleased`, and tag the commit `v<version>`. Fixes are patch, new behaviour
  minor, a changed `.env` contract is major.
- **Do not** add a Dockerfile, an application, a script in
  `/docker-entrypoint.d/` or dependencies.

## Rejected with the user

So they are not proposed again:

- **Generating the certificate on first startup**, for the reasons in Decisions.
- **`nginx:alpine` plain** (94 MB) versus slim (21 MB).
- **Hardening the container** (non-root user, `read_only`, `tmpfs`): the user
  declined it except for the healthcheck and log limits, which are already there.
  It is a few lines in `compose.yaml` at no image cost, if it is ever requested.
